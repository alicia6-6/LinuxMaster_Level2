01 · 리눅스 운영 및 관리

리눅스 개요와 배포판

첫 문제부터 "이 명령/파일은 어느 계열에서 쓰는가"를 묻는 경우가 많아, 배포판 계열부터 구분해두면 이후 패키지·부팅 단원이 훨씬 쉬워집니다.

쉽게 말하면리눅스는 리누스 토르발스가 만든 커널(하드웨어를 직접 관리하는 핵심 프로그램)이고, 여기에 GNU 프로젝트의 각종 도구와 응용 프로그램을 묶어서 배포하는 것이 우리가 흔히 쓰는 "배포판(Distribution)"입니다. 같은 커널을 쓰지만 패키지 관리 방식과 설정 방법이 계열마다 달라서, 시험에서는 "이 명령은 어느 계열 것인가"를 자주 구분해서 묻습니다.
계열대표 배포판패키지 형식·관리자
RedHat 계열RHEL, CentOS, Fedora, Rocky Linuxrpm, yum/dnf
Debian 계열Debian, Ubuntu, Mintdeb, apt/dpkg/dselect
Slackware 계열Slackware, SUSEtgz, zypper(SUSE)
  • 오픈소스·라이선스: GPL은 이 소스를 활용해 만든 프로그램도 소스를 공개해야 하는 강한 카피레프트 라이선스, LGPL은 라이브러리 형태로 링크만 하면 내 프로그램까지 공개할 필요는 없는 완화된 버전, BSD/MIT는 출처만 밝히면 소스 공개 의무 없이 자유롭게 상업적으로도 사용할 수 있는 라이선스입니다.
  • 커널 버전: 예전에는 짝수(2.4, 2.6)가 안정 버전, 홀수(2.5, 2.7)가 개발 버전이었지만 2.6 이후로는 이 규칙이 폐지되고 하나의 버전 계열을 계속 안정적으로 관리하는 방식으로 바뀌었습니다.
  • 가상 콘솔: Ctrl+Alt+F1~F6으로 텍스트 로그인 화면을 전환할 수 있습니다.
기출 함정 dselect·dpkg·apt는 Debian 계열, rpm·yum·dnf는 RedHat 계열, zypper는 openSUSE, alien은 rpm↔deb를 서로 변환해주는 계열 무관 도구입니다.
02 · 리눅스 운영 및 관리

파일 권한과 특수 권한

허가권(퍼미션) 계산과 chmod, 특수 권한(SUID·SGID·Sticky-Bit)은 회차마다 빠지지 않는 최다 출제 영역입니다.

쉽게 말하면리눅스의 모든 파일은 "이 파일의 주인(User)", "같은 그룹(Group)", "그 외 모두(Other)" 세 부류에게 각각 읽기(r)·쓰기(w)·실행(x) 권한을 따로 줄 수 있습니다. 이 3가지 권한을 숫자로 나타낼 때 r=4, w=2, x=1을 더해서 쓰므로, rwx는 4+2+1=7, r-x는 4+0+1=5입니다. chmod 754 file은 "주인은 rwx(7), 그룹은 r-x(5), 기타는 r--(4)"라는 뜻입니다.
r = 4 · w = 2 · x = 1소유자(User) · 그룹(Group) · 기타(Other) 순서로 3자리
  • chmod 755 file: rwxr-xr-x / chmod u+x,g-w file: 기호 방식으로 하나씩 추가·제거
  • chown user:group file: 소유자와 그룹을 동시에 변경 / chgrp group file: 그룹만 변경
  • chgrp -h(또는 chown -h): 심볼릭 링크가 가리키는 원본이 아니라 링크 파일 자체의 소유권을 변경
  • 디렉터리 권한의 의미: r은 목록 확인(ls), w는 그 안에 파일 생성·삭제, x는 그 디렉터리로 들어갈 수 있는 권한(cd)입니다. 파일을 삭제할 수 있는지는 파일 자체가 아니라 그 파일이 들어있는 디렉터리의 w 권한으로 결정됩니다.

umask

쉽게 말하면umask는 "새로 만드는 파일·디렉터리에서 미리 빼둘 권한"입니다. 기본 최대값은 파일 666(디렉터리는 777)이며, 여기서 umask 값을 뺀 만큼이 실제로 만들어지는 권한이 됩니다. umask 022이면 666−022=644(파일), 777−022=755(디렉터리)로 생성됩니다.
예: umask 0002일 때 새 디렉터리를 만들면?

디렉터리 기본값 777에서 002를 빼면 775 → drwxrwxr-x

특수 권한(SUID·SGID·Sticky-Bit)

권한숫자대상의미
SetUID4000실행 파일실행하는 동안 소유자 권한으로 동작 (예: /usr/bin/passwd)
SetGID2000실행 파일실행하는 동안 소유 그룹 권한으로 동작
SetGID2000디렉터리그 안에 새로 생성되는 파일의 그룹을 디렉터리와 동일하게 상속
Sticky-Bit1000디렉터리디렉터리는 누구나 쓸 수 있어도, 그 안의 파일은 만든 사람(소유자)만 삭제 가능 (예: /tmp)
  • 기호 표기: SetUID u+s, SetGID g+s, Sticky-Bit o+t
  • ls -l에서 SetUID는 소유자 실행 자리에 s(실행 권한 없으면 대문자 S), Sticky-Bit는 기타 실행 자리에 t(실행 권한 없으면 대문자 T)로 표시됩니다.
  • Sticky-Bit는 보통 디렉터리에 부여하는 것이 실무적 활용 예이며, 파일에 부여하는 것은 의미가 없는(현대 리눅스에서는 무시되는) 경우로 자주 오답 함정에 등장합니다.
  • lsattr로 확장 속성 확인, chattr +i file로 root조차 수정·삭제 불가능한 immutable 속성 부여
기출 함정 "그룹 소유자의 권한으로 실행"으로 바뀌는 명령은 chmod g+s이며, "삭제는 본인 파일만 가능"하게 만드는 것은 chmod o+t(Sticky-Bit)입니다. 이 둘을 헷갈리게 섞은 보기가 자주 나옵니다.
03 · 리눅스 운영 및 관리

사용자·그룹 관리

쉽게 말하면리눅스는 여러 사람이 동시에 쓰는 것을 전제로 만들어졌기 때문에, 모든 파일·프로세스는 "누구 소유인지"가 꼭 있습니다. 계정 정보는 /etc/passwd(누가 있는지), 비밀번호는 /etc/shadow(암호화된 형태로 별도 보관), 그룹 정보는 /etc/group에 나뉘어 저장됩니다. 비밀번호를 별도 파일로 분리한 이유는 /etc/passwd는 누구나 읽을 수 있어야 하지만(사용자 이름 조회용) 암호 해시까지 노출되면 위험하기 때문입니다.

계정 관련 파일

파일내용

  • UID 0은 root(관리자) 전용입니다. 시스템 계정(서비스용)은 보통 UID 1~999(배포판마다 범위 차이), 일반 사용자 계정은 1000번대부터 시작합니다.
  • 로그인 셸이 /sbin/nologin 또는 /bin/false인 계정은 직접 로그인할 수 없는 서비스 전용 계정입니다.
  • who/w는 현재 로그인한 사용자, last는 로그인 성공 이력, lastb는 로그인 실패 이력을 보여줍니다.
기출 함정 chown이 사용자 이름을 UID로 바꿀 때 참조하는 파일은 /etc/passwd입니다. 비밀번호가 들어있는 /etc/shadow와 혼동하지 마세요.
04 · 리눅스 운영 및 관리

파일시스템·디스크·LVM·RAID·쿼터

쉽게 말하면새 디스크를 책장에 비유하면, fdisk(또는 parted)는 책장에 칸막이(파티션)를 나누는 작업이고, mkfs는 각 칸에 책을 정리할 규칙(파일시스템)을 새로 까는 작업이며, mount는 그 책장을 내가 쓰는 방의 특정 위치(디렉터리)에 연결하는 작업입니다. fsck는 책의 색인과 실제 위치가 맞는지 검사하고 고치는 작업입니다.
fdisk -l디스크·파티션 목록/편집(MBR, 2TB 이하)

mkfs.ext4 /dev/sdb1ext4로 포맷
mkfs.xfs /dev/sdb1XFS로 포맷 (mkfs.<종류> 형태로 통일)
mount / umount파일시스템 연결·해제
fsck파일시스템 오류 검사·복구
df -h파일시스템별 사용량 확인
du -sh dir디렉터리 용량 합계 확인

디스크 쿼터(Quota)

쉽게 말하면쿼터는 "사용자별로 디스크를 얼마나 쓸 수 있는지" 상한선을 정해두는 기능입니다. 설정 순서를 하나의 흐름으로 외우면 헷갈리지 않습니다.
quotacheck → edquota → quotaon → repquota검사 → 값 설정 → 활성화 → 현황 확인
  • quotacheck: 파일시스템을 검사해 쿼터 데이터베이스(aquota.user 등)를 만듦
  • edquota user: vi 편집기 형태로 사용자별 용량 제한값을 지정
  • quotaon / quotaoff: 쿼터 기능 켜기/끄기
  • repquota: 설정 내역과 실제 사용 현황 보고서 출력

LVM(Logical Volume Manager)

쉽게 말하면일반 파티션은 한 번 크기를 정하면 나중에 늘리기 번거롭습니다. LVM은 여러 디스크(또는 파티션)를 하나의 커다란 저장소 풀로 묶어두고, 거기서 필요한 만큼 잘라 쓰다가 나중에 공간이 부족하면 풀에서 더 떼어와 유연하게 늘릴 수 있게 해주는 기술입니다.
단계명령의미
1. PVpvcreatePhysical Volume, 실제 디스크/파티션을 LVM 대상으로 초기화
2. VGvgcreateVolume Group, 여러 PV를 하나의 저장소 풀로 묶음
3. LVlvcreateLogical Volume, VG에서 실제 사용할 논리 볼륨을 잘라냄

RAID

레벨방식특징
RAID 0Striping여러 디스크에 데이터를 나눠 써서 속도 향상, 하지만 중복이 없어 안정성 없음
RAID 1Mirroring같은 데이터를 두 디스크에 그대로 복제, 안정성은 높지만 용량 효율은 50%
RAID 5분산 Parity디스크 여러 개에 데이터+패리티(오류 복구용 정보)를 분산 저장, 디스크 1개 고장까지 복구 가능
RAID 6이중 Parity패리티를 두 배로 저장해 디스크 2개까지 동시 고장에도 복구 가능

05 · 리눅스 운영 및 관리

프로세스와 작업 스케줄링

쉽게 말하면프로세스는 "지금 실행 중인 프로그램 하나하나"를 부르는 말입니다. ps·top은 지금 어떤 프로세스들이 돌고 있는지 보여주는 "현황판"이고, kill은 그중 하나를 강제로 끄는 "전원 버튼"입니다. 보통 명령을 실행하면 끝날 때까지 화면을 붙잡고 기다려야(포그라운드) 하는데, 뒤에 &를 붙이면 그 작업을 뒤로 보내고(백그라운드) 곧바로 다른 명령을 이어서 입력할 수 있습니다.
ps -ef / ps aux전체 프로세스 스냅샷

텍스트 처리 3형제: grep·sed·awk

쉽게 말하면세 명령은 모두 "글자로 된 파일을 다루는 도구"인데 하는 일이 다릅니다. grep은 문서 더미에서 원하는 줄만 "찾아내는" 형광펜, sed는 찾은 단어를 "바꿔치는" 자동 수정펜, awk는 표처럼 칸(공백·탭 등)으로 나뉜 데이터에서 원하는 열(칸)만 "뽑아내는" 가위입니다. 셋 다 화면에 결과만 보여줄 뿐 원본 파일은 그대로 두는 것이 기본이라, 마음 편히 연습해도 됩니다.
  • grep -i 'text' file: 대소문자 구분 없이 문자열이 포함된 줄 찾기, -v는 제외
  • sed 's/old/new/g' file: 스트림 에디터로 old를 new로 전체(g) 치환
  • awk '{print $1}' file: 필드(칸) 단위로 잘라 원하는 열만 출력
  • vi 편집기: i 입력 모드, Esc 명령 모드, :wq 저장 후 종료, :q! 저장 없이 강제 종료, :%s/old/new/g 문서 전체 치환

웹·메일·파일 공유 서버

Apache 웹 서버

쉽게 말하면웹 서버는 "인터넷 매장의 점원"입니다. 손님(브라우저)이 특정 주소로 요청을 보내면, 그 요청을 몇 번 문(포트)으로 받을지, 손님이 아무 파일 이름 없이 그냥 들어왔을 때 어떤 페이지를 보여줄지, 문서는 어느 창고(디렉터리)에서 꺼내올지를 미리 정해둔 규칙(설정 파일)대로 응대합니다. Apache는 이런 역할을 하는 대표적인 오픈소스 웹 서버 프로그램입니다.
항목내용
메인 설정 파일httpd.conf
Listen서비스할 포트 지정(기본 80)
DirectoryIndex디렉터리 접속 시 기본으로 보여줄 파일(index.html 등)
DocumentRoot웹 문서가 위치한 최상위 디렉터리
Timeout요청 처리 대기 시간
KeepAliveTimeout지속 연결 상태에서 다음 요청을 기다리는 시간
LimitRequestBody클라이언트 요청 본문의 최대 크기 제한
VirtualHost한 서버에서 여러 도메인·사이트를 동시에 운영(가상 호스트)

메일 서버

쉽게 말하면메일을 "보낼 때"와 "받아올 때" 쓰는 프로토콜이 다릅니다. 보내는 건 항상 SMTP이고, 받아오는 방식만 POP3(다운로드 후 서버에서 삭제가 기본)과 IMAP(서버에 두고 여러 기기에서 동기화)으로 나뉩니다.
프로토콜포트역할
SMTP25메일 발송(서버↔서버 포함)
POP3110메일을 내려받아 로컬에서 관리
IMAP143서버에 메일을 두고 여러 기기에서 동기화

리눅스 대표 메일 서버 소프트웨어로는 Sendmail, Postfix가 있습니다.

파일 공유: Samba·NFS·FTP

쉽게 말하면셋 다 "내 컴퓨터의 폴더를 다른 컴퓨터와 나눠 쓰게 해주는" 서비스인데, 대상이 다릅니다. Samba는 Windows 컴퓨터와 폴더·프린터를 공유할 때, NFS는 리눅스/유닉스 서버끼리 폴더를 공유할 때, FTP는 운영체제와 상관없이 파일을 인터넷으로 업로드·다운로드할 때 씁니다.
서비스용도핵심 설정 파일
SambaWindows와 파일·프린터 공유(SMB/CIFS 프로토콜)/etc/samba/smb.conf
NFS리눅스/유닉스 간 디렉터리 공유/etc/exports
vsftpd(FTP)파일 업로드·다운로드 전용 서버/etc/vsftpd/vsftpd.conf

보안: 방화벽·SELinux·SSH

쉽게 말하면방화벽은 "어떤 트래픽을 통과시키고 막을지" 규칙을 정하는 문지기입니다. SELinux는 한 단계 더 나아가, 통과한 프로세스라도 "이 프로그램은 이 파일에만 접근할 수 있다"처럼 세밀하게 접근을 제한하는 보안 체계입니다.
도구역할
iptables커널의 netfilter를 이용한 전통적인 방화벽 규칙 관리(체인·테이블 기반)
firewalldZone 개념으로 방화벽 규칙을 동적으로 관리하는 최신 도구
SELinux강제적 접근 제어(MAC)로 프로세스별 세밀한 권한 통제, Enforcing/Permissive/Disabled 모드
SSH암호화된 원격 접속 프로토콜(포트 22), telnet의 평문 통신 문제를 해결
  • iptables -A INPUT -p tcp --dport 22 -j ACCEPT: 22번 포트(SSH) 허용 규칙 추가
  • ssh user@host: 원격 접속, scp: 암호화된 파일 복사
  • root 원격 로그인 차단, 키 기반 인증 사용 등이 SSH 기본 보안 수칙으로 자주 출제됩니다.
14 · 리눅스 활용

가상화·클러스터링

쉽게 말하면가상화는 물리 서버 한 대를 소프트웨어로 여러 대의 "가짜 컴퓨터"처럼 쪼개 쓰는 기술이고, 클러스터링은 반대로 여러 대의 서버를 묶어 한 대처럼 동작시켜 성능이나 안정성을 높이는 기술입니다.
기술설명
Xen초기부터 리눅스 진영에서 널리 쓰인 대표적인 오픈소스 하이퍼바이저
KVM리눅스 커널에 내장된 가상화 모듈 기반 하이퍼바이저
RHEVRedHat의 KVM 기반 엔터프라이즈 가상화 관리 플랫폼

클러스터링 구성 방식

  • HA(High Availability) 클러스터: 한 서버가 장애 나면 대기 중이던 다른 서버가 즉시 이어받아 서비스 중단을 최소화(고가용성)
  • LVS(Linux Virtual Server): 여러 서버로 요청을 분산시키는 로드밸런싱 클러스터
  • HPC(High Performance Computing) 클러스터: 여러 서버의 연산 능력을 합쳐 대규모 계산 작업을 빠르게 처리(고성능 컴퓨팅)
  • 베어울프(Beowulf) 클러스터: 일반 PC를 여러 대 연결해 저비용으로 구성하는 병렬 컴퓨팅 클러스터의 대표 사례
기출 함정 "장애 발생 시 대기 서버가 즉시 이어받는" 방식은 HA 클러스터이고, "여러 서버에 요청을 고르게 나눠주는" 방식은 LVS(로드밸런싱)입니다. 목적이 다르니 설명 문장을 잘 읽고 구분하세요.
15 · 리눅스 활용

클라우드·임베디드·최신 기술

쉽게 말하면클라우드는 "서버·저장공간·소프트웨어를 사지 않고 필요한 만큼 빌려 쓰는 것"입니다. 집을 예로 들면 IaaS는 빈 골조만 빌리고 인테리어는 직접 하는 것(하드웨어만 빌리고 OS·프로그램은 직접 설치), PaaS는 완공된 집에 가구만 들이는 것(실행 환경은 준비되어 있고 내 프로그램만 올림), SaaS는 풀옵션 호텔에 묵는 것(로그인만 하면 바로 사용, 예: 웹메일)에 비유할 수 있습니다.
모델내가 관리하는 범위예시
IaaSOS·런타임·앱까지 전부 직접 설치·관리가상 서버(VM), 스토리지 임대
PaaS내가 만든 애플리케이션 코드만 관리앱 실행 플랫폼, DB 서비스
SaaS관리할 것 없이 사용만 함웹메일, 웹 기반 오피스

임베디드·IoT 보드와 모바일 OS

쉽게 말하면임베디드 보드는 "손바닥만 한 미니 컴퓨터"입니다. 일반 PC처럼 다양한 프로그램을 다 돌릴 수 있는 것도 있고(Raspberry Pi), 센서를 읽고 모터를 움직이는 딱 정해진 한 가지 일만 반복하도록 만들어진 것도 있습니다(Arduino). IoT(사물인터넷)는 이런 작은 기기들이 인터넷에 연결되어 서로 데이터를 주고받는 환경을 말합니다.
이름설명
Raspberry Pi교육·취미용으로 널리 쓰이는 신용카드 크기의 단일보드 컴퓨터, 다양한 리눅스 배포판 구동 가능
Arduino센서·모터 제어에 특화된 마이크로컨트롤러 기반 오픈소스 하드웨어 플랫폼(범용 OS 없이 단순 반복 제어에 특화)
Cubie BoardRaspberry Pi와 유사한 ARM 기반 단일보드 컴퓨터
Tizen리눅스 커널 기반의 삼성 주도 오픈소스 모바일·IoT 운영체제
webOSLG가 스마트TV 등에 사용하는 리눅스 기반 운영체제
기출 함정 "센서 제어" 위주 설명은 Arduino, "완전한 리눅스 OS 구동"이 특징인 설명은 Raspberry Pi로 구분하세요.
