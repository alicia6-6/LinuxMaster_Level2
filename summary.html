01 · 제1과목 리눅스 운영 및 관리 (문항 1~48)

리눅스 개요와 역사·오픈소스 라이선스

시험 1번~3번 단골 출제! 리눅스의 탄생 배경과 소프트웨어 라이선스의 소스코드 공개 의무를 구별하는 문제가 매회 출제됩니다.

쉽게 말하면 자동차에 비유하면 커널(Kernel)은 엔진이고, 배포판(Distribution)은 그 엔진에 핸들, 시트, 내비게이션, 오디오를 달아 소비자가 바로 탈 수 있게 완성차로 만든 것입니다.
1991년 핀란드의 대학생 리누스 토르발스(Linus Torvalds)가 유닉스를 본뜬 '미닉스(Minix)'를 개량해 엔진(리눅스 커널)을 인터넷에 무료 공개했고, 리처드 스톨먼(Richard Stallman)의 자유 소프트웨어 재단(FSF)이 만든 부품(GNU 도구들)과 합쳐져 오늘날의 리눅스(GNU/Linux)가 완성되었습니다.

라이선스소스코드 공개 의무상업적 이용특징 및 대표 소프트웨어

02 · 제1과목 리눅스 운영 및 관리

파일 권한(Permission)과 특수 권한·umask

매회 2~4문항이 무조건 출제되는 최다 빈출 영역! 허가권 숫자 계산, umask, 특수 권한(SUID·SGID·Sticky-Bit)의 원리를 완벽하게 정리합니다.

쉽게 말하면 리눅스는 여러 사람이 함께 쓰는 서버이므로 파일마다 "누가 무엇을 할 수 있는지" 이름표를 붙여둡니다.
이름표의 대상은 3그룹: 소유자(User/u), 소속 그룹(Group/g), 제3자(Other/o)입니다.
할 수 있는 행동은 3가지: 읽기(r=4), 쓰기(w=2), 실행(x=1)입니다. 이 셋을 더한 숫자로 권한을 표현합니다!
r(읽기)=4 · w(쓰기)=2 · x(실행)=1 rwx = 4+2+1 = 7 / rw- = 4+2 = 6 / r-x = 4+1 = 5 / r-- = 4

1. 파일 vs 디렉터리 권한의 결정적 차이 (★초특급 기출)

권한일반 파일에 부여될 때디렉터리(폴더)에 부여될 때
r (읽기, 4)파일 내용 읽기/보기 (cat, vi 등)폴더 안의 파일 목록 보기 (ls)
w (쓰기, 2)파일 내용 수정/저장폴더 안에 파일 생성 및 삭제(rm)
x (실행, 1)프로그램으로 실행하기 (스크립트 실행)그 폴더 안으로 들어가기 (cd) 및 내부 접근
기출 함정: "내가 만든 파일을 남이 지울 수 있는가?"
많은 비전공자가 파일에 쓰기(w) 권한이 없으면 삭제할 수 없다고 착각합니다. 아닙니다!
파일의 삭제 권한은 파일 자체가 아니라 그 파일이 들어있는 '디렉터리의 w 권한'이 결정합니다. 방(폴더) 주인이 방 안의 물건을 버릴 권한을 가지는 것과 같습니다.

2. 권한 및 소유권 변경 명령어

chmod 755 test.sh소유자 rwx(7), 그룹 r-x(5), 기타 r-x(5) 부여
chmod u+x,g-w test.sh기호 모드: 소유자에게 실행 추가(+), 그룹에 쓰기 제거(-)
chown user01 file.txt파일 소유자를 user01로 변경
chown user01:sales file.txt파일 소유자(user01)와 그룹(sales)을 동시에 변경
chgrp sales file.txt소유 그룹만 sales로 변경
chown -R user01 /data-R 옵션: 하위 디렉터리와 모든 파일까지 일괄 재귀 적용
chown -h user01 link_file-h 옵션: 심볼릭 링크 원본이 아닌 '링크 파일 자체'의 소유권 변경
chattr +i file.txtroot조차도 수정/삭제/이름변경 불가능하게 불변 속성(immutable) 부여

3. umask (새 파일/디렉터리 기본 권한 계산법)

쉽게 말하면 공장에서 옷을 만들 때 기본 틀에서 필요 없는 부분을 잘라내는 것과 같습니다.
리눅스에서 새로 만드는 파일의 최대 권한은 666(실행 권한은 보안상 기본 제공 안 함), 디렉터리는 777입니다.
여기서 umask로 지정한 숫자를 빼고 남은 권한으로 실제 파일/폴더가 생성됩니다.
계산 공식과 실전 예시

기본 공식: 파일 생성 권한 = 666 - umask / 디렉터리 생성 권한 = 777 - umask
• 만약 umask 022라면?
  - 파일: 666 - 022 = 644 (-rw-r--r--)
  - 디렉터리: 777 - 022 = 755 (drwxr-xr-x)
• 시험 함정: 홀수 umask (예: umask 027)
  디렉터리는 777 - 027 = 750 (rwxr-x---).
  파일은 666 - 027을 하면 639가 되는데, 9라는 권한은 없습니다! 파일은 원래 x(1)가 없었으므로 1을 뺄 수 없어 짝수로 올림됩니다. 따라서 666에서 027의 마스크를 적용하면 640 (-rw-r-----)이 됩니다.

4. 특수 권한 (SUID · SGID · Sticky-Bit)

일반적인 rwx 외에 보안 및 협업을 위해 맨 앞에 1자리를 더 붙이는 4자리 권한입니다.

특수 권한숫자설정 기호표시 위치(ls -l)핵심 동작 및 대표 사례
SetUID (SUID) 4000 u+s 소유자 x 자리에 s
(x 없으면 대문자 S)		 일반 사용자가 실행하더라도 실행되는 동안에는 파일 소유자(보통 root)의 권한으로 동작함.
• 대표 예: /usr/bin/passwd (일반인이 자기 비번 바꿀 때 잠시 root 권한으로 /etc/shadow 수정)
SetGID (SGID) 2000 g+s 그룹 x 자리에 s
(x 없으면 대문자 S)		 1. 실행 파일: 실행 중 소유 그룹의 권한으로 동작.
2. 디렉터리: 이 디렉터리 안에 새로 만드는 파일의 소유 그룹이 디렉터리의 그룹으로 자동 상속됨 (공동 프로젝트 폴더용).
Sticky Bit 1000 o+t 기타(other) x 자리에 t
(x 없으면 대문자 T)		 누구나 파일을 만들고 쓸 수 있는 공용 디렉터리이지만, 삭제나 이름 변경은 오직 자기가 만든 파일만 가능함 (남의 파일 삭제 불가!).
• 대표 예: 공용 임시 폴더 /tmp (권한 1777, drwxrwxrwt)
기출 함정
1. ls -l 출력 결과 -rwsr-xr-x ➔ 맨 앞 소유자 자리에 소문자 s가 있으므로 SetUID(4755)입니다.
2. 대문자 S나 T로 표시되는 이유는? ➔ 본래 실행 권한(x)이 없는 파일에 특수 권한만 줬을 때 경고 의미로 대문자로 표시됩니다.
3. Sticky Bit는 일반 파일에 부여하면 현대 리눅스에서는 아무런 효력이 없으며, 공용 디렉터리에 부여할 때만 의미가 있습니다.
03 · 제1과목 리눅스 운영 및 관리

사용자·그룹 관리와 핵심 설정 파일

계정 생성 옵션, 비밀번호 만료 정책(chage), 사용자 정보 파일의 필드 구조를 묻는 문제가 집중 출제됩니다.

쉽게 말하면 회사의 인사카드와 같습니다. 회사 직원 명부는 누구나 볼 수 있지만(/etc/passwd), 개인 비밀번호와 연봉 정보는 금고에 따로 잠가둡니다(/etc/shadow).
새 직원이 입사하면(useradd) 기본 사무용품 세트(/etc/skel)를 책상에 자동으로 깔아줍니다.

1. 계정 핵심 파일 3종 필드 분석 (외우면 2문제 맞힘!)

콜론(:)으로 구분되는 각 자리의 의미를 묻는 문제가 빈출됩니다.

파일필드 구성 및 순서핵심 설명
/etc/passwd 사용자명 : 암호(x) : UID : GID : 설명(GECOS) : 홈디렉터리 : 기본셸 모든 사용자가 읽기 가능. 두 번째 자리 x는 실제 암호가 /etc/shadow에 암호화되어 보관되어 있다는 뜻. UID 0은 root.
/etc/shadow 사용자명 : 암호해시 : 최종변경일 : 최소사용일 : 최대사용일 : 경고일 : 유예일 : 만료일 : 예약 root만 읽기 가능. 암호해시가 $6$...이면 SHA-512, $5$...이면 SHA-256, $1$...이면 MD5 알고리즘 사용. 암호 자리가 !나 *면 잠긴 계정.
/etc/group 그룹명 : 그룹암호(x) : GID : 소속사용자목록(콤마구분) 사용자의 2차(보조) 그룹 명단이 저장됨.

2. 계정 관리 필수 명령어

useradd -u 1500 -g 1000 -G wheel -d /home/sam -s /bin/bash samUID(1500), 기본그룹(1000), 보조그룹(wheel), 홈디렉터리, 셸 지정 계정생성
usermod -aG sales sam-aG 옵션: 기존 소속 그룹 유지하면서 sales 보조 그룹 추가 (a 빠지면 기존 그룹 다 날아감!)
usermod -L sam / -U sam계정 잠금(-L, Lock) / 잠금 해제(-U, Unlock)
userdel -r sam-r 옵션: 사용자의 홈 디렉터리와 메일함까지 말끔하게 동시 삭제
passwd -l sam / -u sam비밀번호 잠금 / 해제 (shadow의 암호 앞에 !를 붙임)
chage -l sam비밀번호 만료 주기 및 계정 유효기간 정보 조회
chage -M 90 -W 7 sam최대 사용기간 90일(-M), 만료 7일 전부터 경고 메시지(-W) 출력
su user01 vs su - user01su는 사용자만 전환, su -는 해당 사용자의 환경변수(PATH, 홈)까지 완전 전환
  • /etc/default/useradd & /etc/login.defs: 계정 생성 시 기본 적용되는 홈 디렉터리 경로, 기본 셸, 기본 UID/GID 시작 번호, 기본 비밀번호 만료 정책 정의.
  • /etc/skel: useradd -m으로 새 홈 디렉터리를 만들 때 .bashrc, .bash_profile 같은 기본 뼈대 파일들이 자동으로 복사되어 들어가는 원본 템플릿 디렉터리.

3. LVM (Logical Volume Manager) - 피자 반죽 비유

쉽게 말하면 디스크 크기가 작아서 고민될 때, 작은 밀가루 반죽 덩어리들(물리 디스크: PV)을 한데 모아 커다란 한 덩어리 반죽(저장소 풀: VG)으로 뭉쳐놓은 다음, 거기서 필요한 크기만큼 피자 도우(논리 볼륨: LV)를 떼어내 쓰는 기술입니다. 나중에 용량이 모자라면 반죽 덩어리(LV)를 주물러서 즉시 크기를 늘릴 수 있습니다!
단계구성 요소생성 명령크기 확장 명령상세 확인

2단계VG (Volume Group, 볼륨 그룹)vgcreate myVG /dev/sdb1vgextendvgdisplay, vgs
3단계LV (Logical Volume, 논리 볼륨)lvcreate -L 20G -n myLV myVGlvextendlvdisplay, lvs

  • LE (Logical Extent): LV가 할당받는 기본 단위로, PE와 1:1로 매핑됩니다.

5. 디스크 쿼터(Quota) 설정 4단계 순서 (무조건 출제)

  • 블록(Block) 제한: 실제 사용하는 디스크 용량(KB 단위)을 제한.
  • 아이노드(Inode) 제한: 사용자가 만들 수 있는 총 파일 개수를 제한.
  • Soft Limit: 초과 시 경고 메시지가 뜨며 정해진 유예기간(Grace Period, 기본 7일) 동안만 임시 허용.

네트워크 기초와 OSI 7계층·프로토콜

OSI 7계층의 순서, 각 계층별 전송 단위(PDU), 대표 장비, ARP/ICMP/TCP/UDP 프로토콜을 정리합니다.

쉽게 말하면 편지를 부치는 과정과 같습니다.
편지지에 글을 쓰고(응용/표현/세션), 규격 편지봉투에 넣어 우편번호를 적고(전송 계층: 포트번호), 주소를 적어(네트워크 계층: IP 주소), 우체부의 오토바이에 실어(데이터링크: MAC 주소/이더넷), 도로를 따라 실물 종이를 배달합니다(물리 계층: 케이블선).

1. OSI 7계층 vs TCP/IP 4계층과 데이터 단위(PDU)

OSI 계층데이터 전송 단위 (PDU)대표 장비대표 프로토콜 및 기출 포인트
7. 응용 (Application)메시지 / 데이터게이트웨이 (Gateway)HTTP, FTP, SSH, Telnet, SMTP, POP3, DNS, DHCP
6. 표현 (Presentation)데이터 암호화, 압축, 코드 변환 (ASCII, JPEG)
5. 세션 (Session)통신 장치 간의 논리적 연결(세션) 수립 및 유지 (RPC, NetBIOS)
4. 전송 (Transport)세그먼트 (Segment)L4 스위치TCP (신뢰성/연결지향), UDP (속도/비연결) / 포트 번호 다룸
3. 네트워크 (Network)패킷 (Packet)라우터 (Router), L3 스위치IP, ICMP, ARP, RARP / IP 주소를 통한 최적 경로(라우팅) 결정

2. 핵심 프로토콜 정리 (ARP · RARP · ICMP · TCP · UDP)

  • ARP (Address Resolution Protocol): 논리적 IP 주소를 물리적 MAC(하드웨어) 주소로 변환해주는 프로토콜 (조회 명령: arp -a).
  • RARP (Reverse ARP): 반대로 MAC 주소를 바탕으로 자신의 IP 주소를 알아내는 프로토콜.
  • ICMP (Internet Control Message Protocol): 네트워크 오류 보고 및 상태 진단 프로토콜 (대표 도구: ping, traceroute).
  • TCP vs UDP:
    - TCP: 3-Way Handshake로 연결을 확인하고 보내는 신뢰성 프로토콜 (패킷 손실 시 재전송, 순서 보장). 웹, 파일전송, 메일에 사용.
    - UDP: 확인 과정 없이 데이터만 고속으로 쏘는 비연결성 프로토콜 (헤더가 작고 빠름). DNS 질의, DHCP, 실시간 스트리밍, SNMP에 사용.

3. 케이블과 커넥터

  • UTP (Unshielded Twisted Pair): 피복 차폐가 없는 가장 흔한 랜선. 커넥터 규격은 RJ-45.
  • STP (Shielded Twisted Pair): 금속 호일로 전자기 간섭을 차폐한 꼬임선 (공장 등 노이즈 많은 환경용).
  • 동축 케이블 (Coaxial): CCTV나 과거 10BASE2에서 쓰던 케이블. 커넥터는 꽂고 돌려서 고정하는 BNC 커넥터.

2. 비전공자도 10초 만에 푸는 '마법의 256 서브넷 계산 공식' (★핵심)

2진수 8자리 변환을 몰라도 시험 문제를 10초 만에 푸는 치트키입니다.

기출 공식

1. 서브넷 1개당 할당되는 전체 IP 개수 = 256 - X
2. 실제 컴퓨터에 줄 수 있는 '가용 호스트 IP 개수' = (256 - X) - 2
  *(왜 2개를 뺄까요? 맨 앞 '네트워크 대표 주소'와 맨 뒤 '브로드캐스트 전송 주소' 2개는 컴퓨터에 할당할 수 없기 때문입니다!)*
3. 쪼개지는 총 서브넷 개수 = 256 / (256 - X)

/25 (255.255.255.128) 126개 256-128=128개 IP → 호스트 126개 (서브넷 2개)
/26 (255.255.255.192) 62개 256-192=64개 IP → 호스트 62개 (서브넷 4개)
/27 (255.255.255.224) 30개 256-224=32개 IP → 호스트 30개 (서브넷 8개)

3. IPv6 핵심 특징 (IPv4와의 비교)

  • 주소 길이가 128비트 (16비트씩 8개 그룹, 16진수로 표기하며 콜론 :으로 구분).
  • 0이 연속되는 부분은 ::로 주소 내에서 딱 한 번만 축약 가능.
  • 전송 방식: 유니캐스트(1:1), 멀티캐스트(1:다수), 애니캐스트(1:가장가까운하나)로 구성.
  • 시험 단골: IPv6에는 전체 방송 개념인 **브로드캐스트(Broadcast)가 없습니다!**

2. DHCP IP 자동 할당 4단계 (DORA 과정)

DHCP 임대 4단계: Discover → Offer → Request → ACK (DORA) 클라이언트 찾기 → 서버 제안 → 클라이언트 요청 → 서버 승인/확정
  • 1. DHCP Discover: 클라이언트가 "여기 IP 빌려줄 DHCP 서버 있나요?" 하고 브로드캐스트로 찾음.
  • 2. DHCP Offer: 서버가 "이 IP 주소 어때요?" 하고 임대할 정보를 제안함.
  • 3. DHCP Request: 클라이언트가 "그 IP로 빌려 쓸게요!" 하고 공식 요청함.
  • 4. DHCP ACK: 서버가 "최종 승인합니다. 며칠 동안 쓰세요" 하고 확정 통보함.
  • DHCP 설정 파일: /etc/dhcp/dhcpd.conf, 사용 포트: 서버 67번, 클라이언트 68번 (UDP).

  • 주요 메일 서버 소프트웨어:

    - Postfix: Sendmail과 호환되면서 보안성과 속도를 크게 개선한 현대적 메일 서버 (메인 설정 파일: /etc/postfix/main.cf).

16 · 제2과목 리눅스 활용

리눅스 보안: iptables 방화벽·TCP Wrapper·SELinux

iptables 테이블과 체인 문법, TCP Wrapper의 hosts.allow/deny 판정 우선순위, SELinux의 3대 동작 모드가 출제됩니다.

1. 패킷 필터링 방화벽: iptables

리눅스 커널의 netfilter 기능을 제어하는 전통적인 방화벽 도구입니다.

  • 3대 기본 테이블: filter (패킷 허용/차단 기본 테이블), nat (IP/포트 주소 변환), mangle (특수 패킷 조작).
  • filter 테이블의 기본 체인 3가지:
    - INPUT: 내 리눅스 서버 안으로 들어오는 패킷에 적용
    - OUTPUT: 내 리눅스 서버에서 밖으로 나가는 패킷에 적용
    - FORWARD: 내 서버를 거쳐 다른 목적지로 통과해 지나가는 패킷에 적용 (라우터 역할 시)
  • 주요 명령 옵션: -A (체인 끝에 규칙 추가), -D (규칙 삭제), -I (체인 맨 앞에 규칙 삽입), -p (프로토콜 tcp/udp/icmp), -s (출발지 IP), -d (목적지 IP), --dport (목적지 포트), -j (타깃: ACCEPT 허용, DROP 말없이 버림, REJECT 거부 메시지 보내고 차단).
iptables 실전 기출 규칙 해석

iptables -A INPUT -p tcp -s 192.168.1.0/24 --dport 22 -j ACCEPT
➔ "192.168.1.0 대역에서 들어오는(-s) 22번 포트(SSH) TCP 패킷(-p tcp)을 허용(-j ACCEPT)하는 규칙을 INPUT 체인 끝에 추가(-A)한다."

2. 네트워크 접근 제어: TCP Wrapper

쉽게 말하면 나이트클럽 입구의 기도와 같습니다. 손님이 오면 1차로 "VIP 명단(hosts.allow)"에 있는지 확인하고, 있으면 무조건 입장시킵니다. VIP 명단에 없으면 2차로 "블랙리스트(hosts.deny)"를 확인하여 있으면 쫓아냅니다. 둘 다 안 적혀 있으면 평범한 손님이므로 입장시킵니다.
TCP Wrapper 판정 순서: hosts.allow 확인 → hosts.deny 확인 → 둘 다 없으면 기본 허용 설정 형식: [데몬명] : [클라이언트 IP 또는 호스트]
  • 예: /etc/hosts.allow에 sshd : 192.168.1. (192.168.1. 대역은 SSH 허용)
  • 예: /etc/hosts.deny에 ALL : ALL (그 외 모든 사용자의 모든 서비스 접속 차단)

3. SELinux (Security-Enhanced Linux) 3대 동작 모드

미국 국가안보국(NSA)이 개발한 강력한 강제적 접근 제어(MAC) 보안 체계입니다.

모드동작 방식특징
Enforcing보안 정책을 엄격히 강제 적용하고 위반 시 즉시 차단차단하고 차단 내역을 로그에 기록함 (기본 모드)
Permissive보안 정책을 차단하지 않고 허용하되, 경고 로그만 기록시스템 문제 해결 및 정책 테스트 시 사용
DisabledSELinux 기능 자체를 완전히 끔보안 검사를 일체 수행하지 않음
getenforce현재 활성화된 SELinux 모드 확인 (Enforcing / Permissive / Disabled)
setenforce 1 / setenforce 0SELinux 모드를 즉시 변경 (1: Enforcing, 0: Permissive)
/etc/selinux/config시스템 재부팅 후에도 유지되도록 영구 설정하는 파일 (SELINUX=enforcing)
17 · 제2과목 리눅스 활용

가상화·클러스터링·클라우드·임베디드 리눅스

가상화 하이퍼바이저 유형, 클러스터링 3대 방식, 클라우드 서비스 모델(IaaS, PaaS, SaaS), 단일보드 컴퓨터(라즈베리파이 vs 아두이노)를 정리합니다.

1. 가상화 기술 (하이퍼바이저 Type 1 vs Type 2)

유형구조대표 기술특징
Type 1
(베어메탈형)		하드웨어 바로 위에 하이퍼바이저 OS가 직접 구동Xen, KVM, VMware ESXi호스트 OS가 없어 오버헤드가 적고 기업용 서버에 적합한 고성능 가상화.
Type 2
(호스트형)		기존 OS(윈도우/리눅스) 위에 프로그램 형태로 구동VirtualBox, VMware Workstation설치가 간편하나 호스트 OS를 거치므로 성능 손실이 있음.
컨테이너
(OS 가상화)		게스트 OS 없이 호스트 커널을 공유하며 격리 공간 제공Docker, Podman, LXC초경량, 초고속 실행. 리눅스 커널의 cgroups(자원격리)와 namespace(공간격리) 기술 사용.

2. 클러스터링 3대 유형 (목적별 구분)

클러스터 종류약자핵심 목적 및 특징
고가용성 클러스터
(HA 클러스터)		 High Availability 무중단 24시간 서비스 보장. 주 서버(Active)가 죽으면 대기 서버(Standby)가 1초 만에 즉시 역할을 이어받음(Failover).
부하분산 클러스터
(LVS 클러스터)		 Load Balancing 인터넷 사용자가 몰릴 때 여러 대의 웹 서버로 요청을 골고루 나눠서 분산시켜 과부하를 방지함.
고성능 계산 클러스터
(HPC 클러스터)		 High Performance Computing 여러 대의 서버 연산 능력을 하나로 묶어 기상 예측, 유전자 분석 등 슈퍼컴퓨터급 대규모 병렬 연산을 수행.
베어울프(Beowulf) - 비싼 슈퍼컴퓨터 대신 저렴한 일반 PC들과 오픈소스 리눅스를 네트워크로 묶어 구축한 HPC 클러스터의 효시.

3. 클라우드 컴퓨팅 서비스 모델 (IaaS · PaaS · SaaS)

쉽게 말하면: 집 구하기 비유
• IaaS: 텅 빈 원룸 골조만 빌리기 (OS부터 가구까지 내가 다 사서 채워야 함. 예: AWS EC2). 대표 오픈소스: OpenStack.
• PaaS: 풀옵션 원룸 (싱크대, 침대 등 개발 환경은 다 갖춰져 있고 나는 내 옷과 컴퓨터만 들고 들어감. 예: Heroku).
• SaaS: 풀서비스 호텔 (내가 관리할 것은 아무것도 없고 카드키 찍고 들어가서 쓰기만 함. 예: 네이버 MYBOX, 구글 드라이브).

4. 임베디드 리눅스와 모바일 OS

  • 라즈베리 파이 (Raspberry Pi): 영국의 라즈베리파이 재단이 교육용으로 만든 신용카드 크기의 ARM 기반 단일보드 컴퓨터(SBC). 완전한 리눅스 OS(Debian 기반 Raspberry Pi OS)를 구동할 수 있음.
  • 아두이노 (Arduino): 초소형 마이크로컨트롤러(MCU) 보드. 완전한 운영체제를 돌릴 수 없으며, 센서 값 읽기와 모터 제어 등 단순 반복 펌웨어 구동에 특화됨.
  • 안드로이드 (Android): 구글이 인수한 리눅스 커널 기반의 스마트폰/태블릿 모바일 운영체제.
  • 타이젠 (Tizen): 리눅스 재단, 삼성전자, 인텔 등이 주도하여 만든 오픈소스 모바일/스마트TV/스마트워치용 운영체제.
  • webOS: LG전자가 스마트TV와 스마트 가전에 적용하고 있는 리눅스 기반 운영체제.
  • QNX: 상용 실시간 운영체제(RTOS)로 자동차 인포테인먼트 시스템 등에 널리 쓰임.
